# 競賽二（棋力預測）：方法與實作紀錄

最後更新：2026-10-05（密集決策點兩模型版本 0.6609，見第 11 節）。
英文版的指令速查與最新數字在 [README.md](README.md)；本文件記錄「做了什麼、為什麼、結果如何、踩過的坑」。

> **重要限制**：本文件所有分數都是**自己切的驗證集（代理分數）**，不是官方排行榜。官方 Public 要等 2026-11-04 測試集釋出才有。
> 官方做法在我的驗證集上重現出 0.437，官方回報 Public 為 0.4631，所以代理的尺度大致可信，但不等於官方成績。

## 1. 任務與評分

- 輸入：同一位玩家 5 到 20 局棋譜（含每局該玩家的執色）。輸出：10 個有序等級之一 `D C B A 1D 2D 3D 4D 5D 6D`。
- 計分：猜中 1 分、差一級 e^-1 ≈ 0.368 分、其餘 0 分；總分是所有題目的平均。
- 官方 baseline（教學 notebook）：棋盤最後 250 個盤面（黑／白兩個平面，共 500 通道）→ 20 個殘差塊的 ResNet → 10 類，
  交叉熵、AdamW lr 1e-3、5 個 epoch，同一題多局把 softmax 平均後取最大機率。Public 0.4631。

## 2. 資料與驗證協議

- 訓練資料：100 萬局，每個等級 10 萬局，8,007 位玩家（每位玩家只屬於一個等級），`data/training/train_*.csv`。
- **玩家不重疊驗證集（val cohort）**：每個等級 40 位、每人 20 局，共 400 位玩家、8,000 局。所有模型訓練都排除這 400 位玩家
  （`train_eval.py` 與各訓練腳本都有 assert）。
- 題目模擬：從每位驗證玩家隨機抽 k ∈ [5, 20] 局當一題，`simulate_questions`（`train_eval.py`）。
- 融合權重與聚合器用「玩家分兩半／五折」交叉擬合：一半擬合、另一半評分，避免用驗證標籤選自己的權重（`blend_eval.py`、`question_aggregator.py`）。
- 信賴區間：對 400 位玩家做配對 bootstrap（`question_aggregator.py` 內的 `bootstrap`）。
- 內測集（holdout test）：另外抽 400 位完全沒碰過的玩家，做成官方格式的 public／private，所有模型排除他們重訓（第 8 節）。

## 3. 特徵與模型（四條線）

### 3.1 KataGo + HumanSL 逐步特徵 → Transformer（最強的單一特徵線）
- 抽取：`extract_rank_features.py`。每局均勻取 32 個「該玩家本人」的決策點，KataGo NBT 模型 1 visit，記錄這手棋在
  一般 policy 與 **10 個 HumanSL 棋力 profile**（`rank_11k, 8k, 5k, 2k, 1d..6d`）下的 surprisal、log rank、entropy
  （共 11 模型 × 3 = 33 通道）。這是競賽一的特徵形式，但 HumanSL 從 3 個 profile 擴成 10 個。
- 價值特徵：`extract_value_features.py`（重用競賽一的 transition token）。每手的勝率與目數損失、ownership 變化幾何，共 32 通道。
- 模型：`transformer_rank.py`。43（或加價值特徵後 75）維 token → Linear(128) → 位置 embedding → 3 層 Transformer
  （4 heads、FFN 384、pre-norm）→ attention pooling → **cumulative-link 有序輸出頭**（一個分數加 9 個遞增門檻）。
  訓練時隨機丟 15% 決策點、加小雜訊，內部驗證用玩家不重疊的 10% 訓練玩家挑最佳 epoch，3 個種子平均。
- 引擎加速：`PipelinedKataGo`（同時保持 3 批在進行）、同一張 GPU 開 2 個進程、`numAnalysisThreads=160`、縮小 NN cache。
  KataGo 每次評估會隨機選棋盤對稱，所以重複抽取同一局會有約 0.07 的 surprisal 雜訊（固有，不是 bug）。

### 3.2 落子序列 Transformer（用全部 90 萬局，不需引擎）
- 資料：`scripts/prep_moves.py` 把每局轉成落子 token（位置、顏色），`all_moves.npz`（前 256 手）與 `all_moves512.npz`（前 512 手）。
- 模型：`move_transformer.py`。位置／顏色／「是否為被評估玩家的顏色」／手數 embedding，4 層、d=192、約 190 萬參數，attention pooling，同樣的有序輸出頭。
- 訓練時對 8 種棋盤對稱隨機增強，推論取 8 種對稱平均。
- 單獨很弱（單局 Top-1 約 0.17），但帶有 KataGo 特徵沒有的資訊，融合權重約 0.2。

### 3.3 官方架構棋盤 ResNet（重現與強化）
- `resnet_rank.py`，網路直接用官方 `network.py` 的 `GoRankResNet`（我只在自己的子類別把 `view` 換成 `reshape`，運算相同）。
- 棋盤狀態用 `board_sim.py`（numba 實作的 19×19 規則模擬：提子、自殺）即時產生，已和 sgfmill 逐盤對照 60/60 一致，約 1.6 毫秒／局。
- 官方重現：常數學習率 1e-3、5 個 epoch（`resnet5`）。強化版：**one-cycle 餘弦學習率、8 個 epoch**（`resnet8c`）。
- 試過但沒有增益：玩家顏色平面、8 種對稱增強（`--colour-plane --symmetry-aug`）。

### 3.4 融合與聚合
- `blend_eval.py`：把各模型每局機率做**加權對數機率融合**（softmax(Σ w_m log p_m)，權重最小化每局 NLL）。
- **期望分數解碼**（`rank_lib.decode`）：選使 `p_c + e^-1 (p_{c-1} + p_{c+1})` 最大的等級，而不是取最大機率。同一個模型單靠這個解碼就約 +0.06。
- **學習式題目聚合器**（`question_aggregator.py`）：特徵為各模型在該題各局的平均對數機率（再加 k），用 L2 正則的多項式 logistic regression（C≈0.02）
  學「怎麼合併多局」，輸出機率再做期望分數解碼。用驗證玩家訓練、玩家分折評估。

## 4. 結果（驗證集代理分數）

題目級、官方計分；括號為解碼方式。誤差約 ±0.01 到 0.02（400 位玩家）。

| 模型／流程 | 題目級分數 | 備註 |
| --- | --- | --- |
| 官方 ResNet 重現（5 epoch、常數 LR） | **0.437**（取最大）／0.496（期望） | 官方 Public 0.4631 |
| 梯度提升＋logistic（1021 維 profile） | 0.481（期望） | 第一版 |
| Transformer，43 維 token，3 種子 | 0.515（期望） | 單種子約 0.518 到 0.522 |
| Transformer 加價值特徵（75 維），3 種子 | 0.534（期望）／0.521（對數平均） | 單局 Top-1 0.248 → 0.261 |
| 落子序列 Transformer | 0.369（期望） | 單局 Top-1 0.174 |
| ResNet 加顏色平面＋對稱增強 | 0.435（取最大）／0.473（期望） | 無增益 |
| **ResNet 餘弦 8 epoch** | **0.519**（取最大）／0.531（期望） | 同架構，訓練設定不同 |
| 三模型融合（價值 Transformer＋落子＋官方 ResNet） | 0.507（取最大）／**0.572 到 0.575**（期望） | 權重交叉擬合 |
| 融合換成餘弦 ResNet | 0.576／0.571 | 持平，融合已飽和在約 0.575 |
| **融合＋學習式聚合器** | **0.595 到 0.597** | 五折玩家分折；固定合併同一批題目 0.573 |

- 聚合器對官方規則的領先：+0.160，bootstrap 95% 區間 [+0.12, +0.20]（四模型版 +0.159、[+0.122, +0.196]）。
- 聚合器對 C 不敏感：C 在 0.01 到 0.05 之間分數 0.595 到 0.597，過大（3）與過小（0.0003）都會下降。

### 如何誠實解讀「領先官方」
1. 領先裡有很大一部分是**解碼與聚合方式**（期望分數解碼、學習式聚合），不是模型本身。同樣用期望解碼，官方 ResNet 是 0.496，我的融合 0.572，差約 +0.08；加聚合器後約 +0.10。
2. **官方架構換成餘弦學習率與 8 個 epoch 就能到 0.519**，所以「官方做法」的分數取決於訓練設定；我的 0.437 是照教學設定的忠實重現。
3. 代理分數有選擇偏誤（解碼方式、C、模型組合是在同一批驗證玩家上挑的），所以才要建第 8 節的內測集。

## 5. 學習曲線與負面結果

- 資料量：KataGo 特徵 Transformer 用 25%／50%／100% 訓練玩家得 0.495／0.522／0.518，**超過約 7,600 局後不再進步**，瓶頸在特徵資訊量，不是資料量。
- 價值特徵（勝率／目數損失、ownership）只有小幅增益（約 +0.005 到 +0.02），低於預期。
- 顏色平面、對稱增強對 ResNet 無增益；ResNet 在第 6 個 epoch 之後開始過擬合。
- 單局準確度卡在約 0.25，且題目局數增加只帶來有限進步，推測是玩家層級的系統偏差。

## 6. 測試日流程（最新版：只需抽一種密集特徵；已用內測集完整驗證）

```
scripts/test_to_games.py --tests-dir <官方測試 csv 目錄>
# 密集 KataGo 特徵（每局最多 96 個決策點，一般模型＋HumanSL rank_5k/1d/5d），4 個進程在兩張 GPU：
#   把 scripts/run_extraction96.sh 內的 `holdout val train` 改成 `test`（輸出 features/feat96/test）
scripts/prep_test_moves.py            # 落子 token（給落子序列模型與 ResNet 用）
predict_test.py --tests-dir <同上>    # → submission_rank.csv（800 列：question_id, pred_rank）
```

- `predict_test.py` 預設：密集 Transformer 3 種子＋ResNet 餘弦版快照 epoch 5 到 8。舊四模型可用 `--model-set full4` 重現。
  → 加權對數機率融合（權重在驗證集擬合）→ 同一題多局以對數平均合併 → **各等級偏差校正**（驗證集學出）→ 期望分數解碼。
- 選項（皆預設關閉）：`--use-aggregator`、`--balanced`、`--no-offsets`；`--suffix _h` 載入排除內測玩家的重訓版本（只用於內測評估）。
- 抽取時間估計：測試集約 10,000 局，4 個進程約 0.4 到 0.5 局/秒/進程，約 1.5 到 2 小時。
- 已用假測試集（80 題）與內測集（400 題）完整跑過；內測集 `python predict_test.py ... --feat features/feat96/holdout --suffix _h` 得 0.6561。
- **測試日要先檢查**：測試玩家是否與訓練玩家重疊（訓練集 `player_id` 是一致的雜湊）；若重疊，競賽一的玩家辨識可以直接查出已知棋力。另外檢查題目局數與執色分布。

## 7. 踩過的坑（之後別再犯）

- `all_moves*.npz` 是**依等級排序**存放的：不可用 `[:N]` 當驗證子集（曾導致 ResNet 內部驗證只剩 5 個等級，Top-1 被灌水到 0.386）。
- 官方 `GoRankResNet.forward` 的 `view` 與 `channels_last` 不相容，要用 `reshape`（不要改官方檔案，用子類別）。
- 第一版落子資料只取前 256 手，29% 的棋局被截掉終盤；ResNet 需要完整長度，所以另做 512 版。
- npz 的字串欄位在 pandas 3 會變成 object 陣列，載入要 `allow_pickle=True` 並轉成 `str`。
- 在 bash 用 `pkill -f <字串>` 會把自己的 shell 殺掉（指令列含該字串），要用 PID。
- 多個 `&&` 串起來後面加 `&` 會整串進背景，後續指令可能搶先執行。
- 機器是共用的：訓練要限制 BLAS 執行緒（`OMP_NUM_THREADS=4`），KataGo 要用分片模式（啟動約 100 秒）。

## 8. 內測集（已完成）

目的：用一份**完全沒被碰過**的官方格式測試集，無偏地量出「官方做法」與「我的整條流程」各是多少，並檢驗代理分數的可信度。

- 建立：`scripts/make_holdout_test.py`。400 位玩家（每等級 40 位，需有 ≥20 局、不在驗證集），每人一題（k ∈ [5, 20]），
  200 題 public＋200 題 private，共 4,950 局。玩家名單 `features/holdout/players.txt`，題目 `features/holdout/tests/`（含 `labels.csv`）。
- 所有模型加上 `--exclude-players features/holdout/players.txt` 重訓，標籤後綴 `_h`：`transformer_v_h`、`move_h`、`resnet5_h`（官方重現）、`resnet8c_h`（餘弦）。
- 內測集特徵：`features/feat/holdout`、`features/feat_value/holdout`、`features/moves/holdout_moves.npz`。
- 流程（已完成）：用 `_h` 模型在驗證集上的輸出重新擬合融合權重與聚合器（`aggregator_h.pkl`）→ `predict_test.py --suffix _h --dump`
  對內測集 400 題推論 → `eval_holdout.py` 評分（融合權重與聚合器只用驗證玩家擬合，內測玩家從未參與任何擬合）。

### 如何解讀內測集結果
1. 這是目前最可信的數字：玩家從未被任何模型或任何擬合步驟看過，SE 約 0.02。
2. 教學做法重現在內測集只有 0.403，低於官方回報的 Public 0.4631；先前驗證集上兩次重現是 0.437 與 0.415。
   **我重現的官方做法一致地比官方回報低約 0.03 到 0.06**，所以若以官方回報的 0.4631 當基準，領先約 +0.12（0.586 − 0.463，
   兩邊各有約 0.02 的 SE，且測試題不同），而不是 +0.18。
3. 領先中有一大塊來自訓練設定：同一個官方架構改用餘弦學習率就從 0.403 到 0.498（+0.095）。融合再往上約 +0.09。
4. **學習式聚合器在內測集上沒有重現驗證集上的 +0.02**：融合 0.5845 對融合＋聚合器 0.5858，差 +0.001，在雜訊內
   （5 到 9 局反而差 0.03，15 到 20 局好 0.02）。驗證集上的 +0.02 因此應視為樂觀估計。
5. 期望分數解碼在內測集對官方模型沒有增益（+0.003），對餘弦 ResNet 約 +0.02；先前在驗證集上估的 +0.06 也偏樂觀。
6. 仍然不是官方排行榜：測試題的分布、玩家是否與訓練重疊都未知，最終要看 2026-11-04 之後的 Public 分數。

## 10. 平衡解碼與聚合器取捨（未預設啟用，2026-10-04 分析）

`analysis_holdout.py` 在內測集（400 題、每等級 40 題）上的發現：

- 模型有系統性偏差：預測成 A 71 題、2D 60 題（真實各 40），預測成 D、4D、6D 只有 22、28、24 題；各等級單獨的分數 0.44（4D）到 0.78（A）。
- **平衡解碼**（`predict_test.py --balanced`，用匈牙利指派讓每個等級被預測相同次數，最大化期望分數）：
  純融合 0.5845 → **0.643**（+0.059，95% 區間 [+0.028, +0.091]）。
- **前提是測試集各等級題數大致相等**，官方測試集是否均衡未知。穩健性模擬（以 Dirichlet 重抽樣出不均衡的測試集）：
  均衡 +0.04、輕微不均 +0.02、中度不均（α=5）−0.01、明顯不均（α=2）−0.05、很不均（α=1）−0.09。**這是賭測試集均衡，不是免費增益，預設關閉。**
- 平衡解碼加在聚合器之上只有 0.5909（聚合器在均衡的驗證集上訓練，輸出已被拉向均衡），所以若要用平衡解碼應搭配 `--no-aggregator`。
- `predict_test.py` 選項：`--balanced`（預設關）、`--no-aggregator`（預設關；聚合器在內測集上相對純融合只有 +0.001）。
- 測試日的決定依據：官方說明或題目資訊是否能確認各等級均衡；沒有證據時用預設（期望分數解碼，不平衡），風險最低。
- 規則面：這是演算法自動指派，不是人工調整預測，但它依賴對測試集分布的假設。


## 11. 密集決策點（最大的一步提升，2026-10-04 到 05）

**動機**：用現有 32 個決策點的特徵做「每隔 k 個取一個」實驗（`--token-stride`），單局 Top-1 隨決策點數近似線性成長：
8 個 0.169、16 個 0.208、32 個 0.248。每加倍約 +0.04，顯示「每局看多少手」是特徵線的瓶頸。

**降低單位成本**（`--keep-profiles`，32 個決策點、單種子）：

| 保留的 KataGo 模型 | 單局 Top-1 | 內部驗證 NLL |
| --- | --- | --- |
| 全部 11 個（一般＋10 個 HumanSL） | 0.248 | 1.864 |
| **一般＋rank_5k／1d／5d（4 個）** | **0.253** | 1.867 |
| 一般＋rank_1d（2 個） | 0.215 | 2.021 |
| 只有一般模型 | 0.207 | 2.041 |

資訊來自「跨棋力的似然對比」，需要至少兩個相隔較遠的棋力 profile，只放一個沒用；4 個就和 11 個一樣好。價值特徵（勝率／目數損失、ownership）增益在雜訊邊緣，密集版略過。

**密集抽取**（`scripts/run_extraction96.sh`）：每局最多 96 個決策點（平均 90.7 個有效、71% 的棋局滿 96 個）、一般模型加 rank_5k／1d／5d，
4 個進程在兩張 GPU，約 0.3 到 0.5 局/秒/進程，28,161 局共約 8 小時（受同機其他工作影響）。輸出 `features/feat96/{train,val,holdout}`。

| 驗證集單局 Top-1 | 0.248 | **0.308 到 0.312** |
| 驗證集題目級（機率平均＋期望解碼 / 對數平均） | 0.534 / 0.521 | **0.566 / 0.591** |
| 內測集題目級（期望解碼，機率平均 / 對數平均） | 0.526 / 0.517 | **0.589 / 0.623** |

最佳 epoch 在 35 到 40，沒有過擬合，仍有學習空間（可能再加 epoch 或更多決策點）。

### 同期的其他改善（皆已併入預設流程）
- **各等級偏差校正**（`rank_lib.fit_class_offsets`）：模型系統性地把題目判成 A（約 17%，公平為 10%）、少判 D 與 6D，偏差在驗證集與內測集一致。

- **ResNet 快照平均**（`snapshot_probs.py`）：依內部驗證 NLL 挑的 epoch 對題目級分數較差，改用訓練後半段多個 epoch 的平均

  - 實驗 2：本人 × 對手的配對差異；
  - 實驗 3：勝負代理。SGF 沒有勝負、讓子和貼目，改用 KataGo 評估最後一個局面的勝率與目差。

- 完整線性殘差和梯度提升樹都會過擬合。
- 事後觀察：只沿強弱軸整體平移的「shift」殘差，在兩組未見玩家上都是正的（+0.006 至 +0.041），加入勝負代理時最大。但驗證集交叉驗證不支持，而且是看過 26 種設定後才挑出的，要確認需要再一組全新玩家。
